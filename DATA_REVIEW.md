# Atlas data and calculation review

Reviewed 2026-10-10 against Atlas **2026-10-07**. Both workflows and versioned session handoff are implemented; their existing tests pass. **Suitable for qualified presales estimates, not engineering/customer sizing commitments.** Unresolved OEM combinations, power bases and fabric validation remain material. No deployment, catalog-value changes or formula changes were made.

`data/atlas.json` remains the sole application reference catalog: 11 platforms, 30 fabrics, 7 switches, 8 storage records and 5 front-end CPU records. All platform IDs are unique, fabric foreign keys resolve, and cached fabric limits agree with the Technical engine. Only the 11 platform records have record-level source links; fabrics, switches, storage and CPU records rely on explainer links, which do not establish every numeric field. `published`, `partner` and `estimate` describe the inherited catalog classification, not independent verification of a complete configuration. Availability labels are also catalog claims, not allocation/delivery verification.

## Field trace and units

| Inputs/fields | Atlas basis or explicit policy | Sales / Technical behavior |
| --- | --- | --- |
| Identity, vendor, form, availability | `platforms.id/vendor/form/status/availability`; fabrics join via `fabric_options.platform`, switches via `switch` | Stable IDs throughout mapping, handoff and exports. Sales maps node to server and announced to unsized roadmap; Technical can size announced estimates. Cerebras is excluded from the GPU-only Sales wizard. |
| Accelerators, memory, host | `accel_per_system`, `hbm_gb_per_accel`, `host_cpu`, `scale_up`, `su_systems` | Whole-system rounding in both engines. Cerebras memory is SRAM despite the legacy HBM field name; its accelerator unit is a wafer. Scalable-unit presets are not required purchase blocks. |
| Compute power | `system_kw_typ`, `system_kw_peak`, optional `facility_provision_kw`, `power_profiles[].rack_kw`, `cluster_provisioned_kw_per_system` | Sales uses maximum peak/provision rating or explicit OEM full-unit override. Technical uses typical/selected profile and a Cerebras provisioned-load floor. Accelerator TDP is metadata, never a replacement for Sales full-unit power. kW; Sales result/budget fields ending `Mw` are MW. |
| Cooling and density | `cooling`, `rack_options[].id/cooling/systems_per_rack`, `system_ru` | Technical trusts selected density; liquid/water selects PUE 1.20, otherwise 1.40 (including air + RDHx). Sales conservatively classifies mixed cooling and uses OEM height/rack capacity with fixed **40U** usable space; Atlas chassis height is deliberately not an OEM override. Neither engine validates mechanical/thermal feasibility for a specific OEM rack. |
| Workloads | `workloads` boolean flags; `storage.best_for` | Catalog eligibility policy, not proof of physical ability or vendor certification. Sales maps `fine_tuning` to `tuning`, `digital_twin` to `digitalTwin`. All current digital-twin flags are false. Sales storage is a workload shortlist, not platform-specific compatibility. |
| Fabric | `fabric_options` IDs, planes, `plane_gbps`, `gbps_per_gpu`, switch radix/power, validation/recommendation flags | Connection speed is **Gb/s**; aggregate = planes × connection speed. Sales recognizes explicitly named InfiniBand/RoCE; UEC alone stays unmapped. Technical assumes non-blocking Clos and uses per-plane radix, k²/2 two-tier ceiling; beyond it offers pods and one three-tier fabric. No third-tier ceiling enforcement or exact vendor BOM validation. 800G-equivalent optic ends are not physical CPO/pluggable part counts. |
| Storage | `storage_rules.tier_by_workload/read_gbps_per_gpu/write_ratio/usable_tb_per_gpu/hot_tb_per_gpu/capacity_tier_id`; `storage.read_gbps_per_unit/usable_pb_per_unit/kw_per_unit` | Legacy `read_gbps_*` fields mean **GB/s (bytes)** in this engine, not network Gb/s; no eightfold conversion. Workload ratios, hot/cold split, minimum one block and rounding are planning policy. Decimal capacity: 1 PB = 1000 TB. Capacity/usable/raw/effective vendor claims require explicit qualification. Sales does not calculate blocks. |
| Front-end CPU | `frontend_rules.vcpu_per_gpu/control_plane_nodes`; `frontend.vcpu_per_node/node_kw` | Logical vCPU capacity, not physical cores/performance. Technical rounds workload vCPU demand to nodes, adds six control-plane nodes, then estimates power. Per-GPU rules also apply to Cerebras wafers; that is preserved generic policy, not vendor-approved wafer ancillary sizing. |
| Facility/ancillary | Sales `salesAssumptions`; Technical `assumptions` plus embedded HTML logic | Sales: compute × 1.15 × 1.20. Technical: compute ÷ 0.90 × cooling PUE, subject to Cerebras floor. Its bottom-up network/storage/CPU warning **does not increase the facility estimate**. Vendor-defined network power is unknown; zero in this check is not known-zero consumption. Rack counts describe compute footprint only. |

Implementation trace: `src/sales/catalogAdapter.js`, `engine.js`, `fleetGuidance.js`; independently `src/technical/engine.js`, `explorerModel.js`. The Technical engine remains the embedded HTML port, not the separate dataset sizing module. Planning ratios, PUE and topology counts are explicit estimates even where an explainer links to a vendor architecture.

Additional material findings:

- **Fabric validation:** [current DGX SuperPOD B300 architecture](https://docs.nvidia.com/dgx-superpod/reference-architecture/scalable-infrastructure-b300/latest/network-fabrics.html) specifies **two 400G planes per GPU**. Atlas's four 200G option is not thereby NVIDIA-validated. All validation flags lack field-level evidence; recommended does not mean validated. No topology/plane changes applied.
- **Switch SKU and power:** [NVIDIA XDR specifications](https://networking-docs.nvidia.com/xdrswitcheshw/specifications) support Q3400's 144 × 800G radix, but distinguish approximately 2.9 kW passive typical and 7 kW active maximum. Atlas 4 kW including optics is not verified on that basis; Q3450 CPO and Q3401 ratings are different SKUs. [Spectrum-6 hardware manual](https://networking-docs.nvidia.com/sn6000hw/1.3/introduction) supports SN6810 breakout radices; SN6800-LD is specified as 2048 × 200G. Generic SN6800's 512 × 800G needs a matching variant; a family-level claim is insufficient. [Broadcom](https://investors.broadcom.com/news-releases/news-release-details/broadcom-now-shipping-worlds-first-1024-tbps-switch-production) supports 102.4 Tb/s silicon, not a universal OEM chassis power rating. Other switch power assumptions remain unverified configuration estimates.
- **Storage:** [WEKApod datasheet](https://www.weka.io/wp-content/uploads/files/resources/2024/03/WEKApod-Data-Platform-Appliance.pdf) supports Nitro175's 720 GB/s, 1 PB and 8U, but lists 6.4 kW for that example; Atlas combines Prime/Nitro/NeuralMesh and 9 kW. Different generations/layouts cannot be mixed. [IBM Scale 6000 requirements](https://www.ibm.com/docs/en/storage-scale-system/5149-F48?topic=hardware-storage-scale-system-6000-requirements) distinguish 3.2 kW estimated at utilization from 4.8 kW maximum. Capacity/throughput require drive/RAID/workload context. VAST, DDN AI400X3/Infinia, NetApp AFX/EF600, Dell F910/Lightning, Pure EXA and generic object-tier records have no matching record-level evidence for their complete block specifications; mark unresolved rather than adopt product-family maxima.
- **CPU:** [EPYC 9965](https://www.amd.com/en/products/processors/server/epyc/9005-series/amd-epyc-9965.html), [Xeon 6980P](https://www.intel.com/content/www/us/en/products/sku/240777/intel-xeon-6980p-processor-504m-cache-2-00-ghz/specifications.html) and [6990E](https://www.intel.com/content/www/us/en/products/sku/246074/intel-xeon-6990e-processor-576m-cache-2-20-ghz/specifications.html) support thread-count arithmetic; 6990E has no doubled SMT assumption. [AMD Venice overview](https://www.amd.com/en/blogs/2026/the-agentic-era-runs-on-a-cpu-foundation-and-it-s-called.html) and [NVIDIA Vera overview](https://developer.nvidia.com/blog/inside-the-nvidia-rubin-platform-six-new-chips-one-ai-supercomputer/) support CPU capacity concepts. Two-socket node choices, full-node 1.0–1.6 kW and workload vCPU ratios remain assumptions, not CPU specification guarantees.

## Corrections, proposed decisions and verification

**Applied:** qualified both interfaces as reference estimates with catalog date, inherited confidence/availability labels and incompatible OEM-combination warning. Corrected Technical eligibility wording to “not listed ... in Atlas” rather than asserting physical unsuitability. Qualified the confidence explainer separately from its preserved archived text. Both exports now state audit status and units; Technical also identifies source gaps, unknown OEM configuration, raw fabric-validation claims as unverified and fixed-allowance/topology/wafer limitations. Existing missing-specification behavior and assumptions remain visible. No numeric mapping/unit error was demonstrated, so no numeric correction was invented.

**Proposals only; decide before changing ambiguous data:**

1. Select concrete OEM/SKU baselines and separate DGX from HGX variants. Resolve MI355X 16-node density against a documented chassis/rack; use the verified eight-node Gigabyte configuration only if that is the intended baseline.
2. Choose documented typical/maximum/provisioned power bases and measurement scope. Do not replace generic rack/switch/storage values with another SKU's rating. Obtain field-level evidence for Rubin/Helios/Cerebras power and ancillary systems.
3. Resolve B300 plane wiring, Spectrum-6 SKU modes and fabric validation with the vendor; then review workload flags against the intended product scope. Decide whether unverified configurations should remain selectable estimates or be restricted in a later approved change.

**Verification:** 59 tests pass, including five focused audit regressions, eight comparison scenarios, stable identity/unit trace, unknown-value/export qualification, composite density, all existing handoff/refresh/incompatibility tests, and 762 original-explorer parity configurations plus 35 storage/CPU combinations. Production build passed.
